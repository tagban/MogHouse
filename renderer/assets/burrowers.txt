# Models that come up out of the ground rather than simply being there.
#
# A worm does not walk into view. It heaves itself out of the earth where it
# was waiting, which is half of what makes one recognisable - and drawing it
# standing on the surface the instant the server mentions it loses that
# entirely.
#
# One model id per line, decimal, with anything after a '#' ignored.
#
#
# Where these came from
# ---------------------
#
# Not guessed. A creature's model DAT declares the sounds it uses as 0x3D
# chunks (see docs/wiki/Audio-Formats.md), and 17024 and 17025 are a worm
# coming out of the ground and going back under it - identified by ear against
# the retail client. So the creatures that burrow are exactly the creatures
# that reference those two sounds, and the list is a query rather than a
# guess:
#
#     for every model file, collect its 0x3D sound ids
#     keep the models that reference 17024 or 17025
#
# An earlier version of this file was built from the server's mob_pools by
# name, and was wrong on three of its four entries - 2027, 2029 and 3021 are
# not installed or not worms, and only 426 survived. Names in a database
# describe what a thing is called; the sound reference describes what it does.
#
# MOGHOUSE_SPAWN_WATCH=1 still prints the model of anything that appears, for
# a creature that burrows without saying so.

424    # references 17024 and 17025 - out and in
425    # references 17024 and 17025
426    # references 17024 and 17025 - the worm rendered and checked
427    # references 17024 and 17025

# 2413 references only 17025, going under without a matching emergence. Left
# out until something is seen doing it, since half a pair is not evidence of
# the other half.
